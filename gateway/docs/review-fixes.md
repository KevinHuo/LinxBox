## 问题与修复

| 问题 | 修复行为 | 回归证据 |
| --- | --- | --- |
| 持久化绑定缺少账号复核 | 复核 bindings.subject 与设备、Desktop 当前凭据；不匹配返回 PERMISSION_DENIED；目录、详情、查询路由、请求和主动通知共用该边界 | 保留同一 SQLite 文件，重新组装认证和 WebSocket 服务；分别变更设备账号、Desktop 账号、双方账号，旧数据均不可读，旧绑定不可幂等接管 |
| 固件 response 编码后超限 | 发送前检查实际 JSON 字节数；超限改为有界 RESOURCE_EXHAUSTED，应答仍与原请求关联；兜底错误也校验大小和 Schema | 关闭 Desktop JSON HTML 转义构造合法输入；修复前固件响应分别为 120909 / 3309 字节，超出 65536 / 1024 限制；修复后均为界内错误，连接仍可继续读取 |
| 从未上线的设备可以首次绑定 | 在首次写入绑定的事务中检查有效在线连接；离线不写入记录；同一账号已有绑定允许离线幂等读取 | 真实 WebSocket 验证离线失败且数据库无记录、上线首次成功、再次离线仍可读取既有绑定；连接层排除已关闭但尚未注销的连接 |

账号复核还覆盖目录更新、新消息接收设备列表和 MCP 请求过期通知；旧记录和原文保留，
不会因为所属账号变化而自动删除数据或向新账号推送旧请求。
